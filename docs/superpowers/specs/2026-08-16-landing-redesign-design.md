# 랜딩페이지 재구성 설계

작성일: 2026-08-16
대상: `https://chat.deepsecu.co.kr/` (`apps/web/app/page.tsx` + `components/landing/`)

## 1. 배경

현재 랜딩은 메시지 축("근거 없이는 답하지 않습니다")이 선명하고, 기관명 대신 분류만 노출하며 "동의 절차 후 공개"라 밝히는 정직한 태도를 갖고 있다. 이 뼈대는 유지한다.

문제는 세 가지다.

**하나. 만든 기능의 절반이 랜딩에 없다.** 관리자 콘솔에 실제 존재하는 화면은 40개인데 랜딩은 6개만 소개한다. 외부 API 실시간 연동, 보안 센터, 감사 로그, ROI 대시보드, 답변 품질 평가, 대화 분석, 에스컬레이션, 지식 검토, 팀·권한, 미답변 관리가 전부 빠져 있다.

**둘. 사실과 다른 문장이 있다.** ANSWER FLOW STEP 02의 "외부 인터넷을 뒤지지 않습니다"는 외부 API 연동 기능이 들어온 지금 부정확하다.

**셋. 제품을 설명하지 담당자의 이득을 말하지 않는다.** "출처 표시", "가드레일", "지식 갭 분석"은 만든 사람의 언어다. 공공기관 담당자는 순환보직으로 오는 비전문가이고, "내 일이 얼마나 줄어드는가"와 "사고 나면 어떻게 되는가"로 판단한다.

부수적으로 히어로의 챗봇 목업이 실제 위젯과 어긋나 있고(신뢰 배지·하단 고지·게시판형 목록 누락), 첫 화면 아래로는 애니메이션이 전무하다.

## 2. 목표

- 공공기관 담당자가 **"도입하면 이렇게 좋아지는구나"** 를 느끼게 한다
- 이미 구현된 공공기관 특화 기능을 **효과의 언어로** 노출한다
- 히어로 데모를 실제 위젯과 일치시킨다
- 스크롤 기반 동적 효과를 일관된 모션 시스템으로 넣는다
- 셀프서비스 가입 동선을 연다

### 비목표

- 기능 상세 하위 페이지 신설 (원페이지 유지)
- 실제 챗봇을 랜딩에 라이브 임베드 (비용·남용 위험)
- 도입 기관명·로고 공개 (동의 절차 미완)
- 경영평가 점수·등급 향상 주장

## 3. 확정된 방향

| 항목 | 결정 |
|---|---|
| 1차 전환 목표 | 도입 문의(주) + 무료 체험(보조) |
| 히어로 데모 | 실제 위젯 재현 + 타이핑 연출 (라이브 임베드 아님) |
| 페이지 구조 | 원페이지 유지, 밀도 압축 |
| 조직 원리 | **효과 중심** — 담당자의 하루가 어떻게 바뀌는가 |
| 평가 활용 소구 | 전 기관 유형 공통 항목만 |

### 메시지 축의 이동

```
기존   "근거 없이는 답하지 않습니다"      = 이게 무엇인가
변경   "담당자의 하루가 이렇게 바뀝니다"   = 뭐가 좋아지나
```

"근거 없이는 답하지 않습니다"는 버리지 않고 자리를 옮긴다. 그것은 *왜 안전한가*에 대한 답이지 *왜 도입하는가*에 대한 답이 아니다. 담당자는 먼저 "내 일이 줄어드나"를 보고, 그다음에 "사고 나면?"을 본다. 섹션 순서를 그 순서에 맞춘다.

### 용어 전환 규칙

랜딩 전체에서 아래 왼쪽 표현을 쓰지 않는다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 출처 표시 | 이 답이 어느 문서에서 나왔는지 바로 보여줍니다 |
| 가드레일 | 답하면 안 되는 건 아예 안 답합니다 |
| 지식 갭 분석 | 뭘 더 올려야 하는지 알려줍니다 |
| 품질 리포트 | 잘 답하고 있는지 주기적으로 알려줍니다 |
| 에스컬레이션 | 어려운 질문은 담당자에게 넘깁니다 |
| 개인정보 자동 마스킹 | 주민번호를 적어도 자동으로 가립니다 |
| 외부 API 연동 | 공고·채용처럼 매일 바뀌는 정보도 최신으로 |
| 감사 로그 | 누가 언제 뭘 바꿨는지 남습니다 |
| 검색 제어 | 옛날 문서는 잠시 빼둘 수 있습니다 |
| RAG · 임베딩 · 색인 · 청킹 | 한 번도 쓰지 않는다 |

**기존 ANSWER FLOW.** 제목을 담당자의 실제 걱정으로 바꾼다. 4단계 구조는 유지하되 소제목을 담당자 언어로 바꾼다.

| | 기존 소제목 | 변경 |

| 01 | 확정 답변을 먼저 확인합니다 | 정해 둔 답이 있으면 그대로 나갑니다 |
| 02 | 등록된 자료에서 근거를 찾습니다 | 우리가 올린 자료에서만 찾습니다 |
| 03 | 근거가 충분할 때만 답을 만듭니다 | 확실하지 않으면 답하지 않습니다 |

### 8. 평가 때 쓸 자료가 자동으로 쌓입니다 🆕

**목적**: 담당자가 상급자에게 예산을 설득할 명분을 준다.

**점수·등급 향상을 주장하지 않는다.** 평가 체계는 기관 유형마다 다르고(기재부 공공기관 경영평가, 행안부 지방공기업 경영평가, 지자체 합동평가, 교육청 등), 담당자는 편람을 우리보다 잘 안다. 검증 불가능한 숫자를 넣으면 그 자리에서 신뢰를 잃는다.

대신 **증빙이 자동으로 만들어진다**고 말한다. 이건 사실이고 검증 가능하다.

| 평가에서 요구하는 것 | 자동으로 나오는 자료 |
|---|---|
| 대국민(주민) 서비스 개선 | 응대 건수 · 시간대별 · 주제별 |
| 비대면·디지털 서비스 확대 | 24시간 안내 건수, 야간·주말 비중 |
| 개인정보 보호 조치 이행 | 개인정보 입력 차단 기록 |
| 업무 효율화 | 반복 문의 처리 건수 |
| 서비스 품질 관리 | 답변 품질 점검 리포트 |
| 개선 계획 수립 | 답 못한 질문 목록 |

**표현 규칙**: 특정 평가 제도명·지표명·배점을 넣지 않는다. 어느 표에나 있는 일반 항목으로만 쓴다.

| 지표 | 비고 |
|---|---|

**이 숫자는 실적이 아니라 화면 예시다.** 도입 기관 동의 없이 실적을 주장하지 않는다는 원칙(마퀴에서 기관명을 감춘 것과 같은 태도)을 여기서도 지킨다. 밴드에 `관리자 콘솔 예시 화면` 라벨을 명시하고, 캡션으로 "도입 기관의 실제 수치가 아니라 콘솔에서 볼 수 있는 지표의 예시"임을 밝힌다.

마무리 줄이 CTA를 겸한다:

> 기관 유형별 구체적 지표 연결은 문의 주시면 개별 안내드립니다.

여기 들어가는 자료는 전부 이미 구현되어 있다 — 보안 센터, 감사 로그, ROI 대시보드, 지식 갭, 품질 리포트, 대화 분석. 신규 개발 없이 노출만 하면 된다.

## 5. 모션 시스템

세련됨은 효과의 개수가 아니라 값의 일관성에서 나온다. 전 섹션이 아래 토큰만 쓴다.

| 토큰 | 값 | 쓰이는 곳 |
|---|---|---|
| `--dur-quick` | 220ms | 호버·버튼·색 전환 |
| `--dur-base` | 550ms | 스크롤 진입·단계 전환 |
| `--dur-slow` | 900ms | 히어로 로드 시퀀스 |
| `--ease-out` | `cubic-bezier(.22, 1, .36, 1)` | 등장 |
| `--ease-soft` | `cubic-bezier(.4, 0, .2, 1)` | 상태 변화 |
| stagger | 80ms | 그룹 내 순차 지연 |
| distance | 22px | 진입 이동 거리 |

22px를 넘기지 않는다. 40px 이상 움직이면 "동적"이 아니라 "산만"해진다.

### 안전장치 — 타협 불가

**① JS 실패 대비.** 기본 CSS는 전부 보이는 상태다. JS가 로드되어야 `<html>`에 `.js-motion`이 붙고 그때부터 숨김이 시작된다. 스크립트가 죽으면 내용은 그냥 다 보인다.

```
기본 CSS               .rv { opacity: 1; transform: none }
JS 로드 후             html.js-motion .rv { opacity: 0; transform: translateY(22px) }
IntersectionObserver   html.js-motion .rv.in { opacity: 1; transform: none }
```

기존 `landing-hero.tsx:8` 주석이 "opacity로 숨기지 말라"고 경고하는 이유와 같은 문제를 이 게이팅으로 해결한다. 게이팅이 있으면 opacity 페이드를 써도 안전하다.

**② `prefers-reduced-motion` 존중.** OS 설정 시 모든 전환을 끄고 완성 상태를 즉시 표시한다.

**③ 합성 전용 속성.** `transform`과 `opacity`만 애니메이션한다. `width`·`top`·`margin`은 매 프레임 레이아웃을 다시 계산시킨다.

공공기관 납품에서 웹 접근성은 실제 평가 항목이다. 제약이 아니라 근거다.

### 쓰지 않는 것

- 패럴랙스 배경 — 멀미 유발, 접근성 감점, 저사양 기기 버벅임
- 커서 추적 스포트라이트 — 유행이지만 수명이 짧다
- `animation-timeline: view()` — 파이어폭스 미지원. IntersectionObserver로 통일

## 6. 히어로 데모 — 실제 위젯 반영

현재 목업은 실제 위젯과 어긋나 있다.

| 요소 | 현재 목업 | 실제 위젯 |
|---|---|---|
| 헤더 | 어두운 슬레이트 | 기관 브랜드 컬러 |
| 신뢰 배지 | 없음 | `✓ 공식 등록 자료 기반 답변` `🔒 개인정보 자동 보호` |
| 하단 고지 | 없음 | 트러스트 노트 + `Powered by DeepSecu` |
| 전송 버튼 | `↑` 텍스트 | 원형 종이비행기 |
| 헤더 아이콘 | 없음 | 홈·최소화·닫기 |
| 목록형 답변 | 없음 | 게시판형 링크 목록 |

### 색 토큰 — 위젯 실제 값을 그대로 쓴다

| 용도 | 배경 | 테두리 | 글자 | 위젯 클래스 |
|---|---|---|---|---|
| 근거 없음 안내 | `#fffbeb` | `#fde68a` | `#92400e` | `.ieum-outcome-warn` |
| 정보 안내 | `#eff6ff` | `#bfdbfe` | `#1e40af` | `.ieum-outcome-info` |
| 보조 안내 | `#f8fafc` | `#e2e8f0` | `#475569` | `.ieum-outcome-muted` |

현재 목업의 경고색(`amber-50`/`amber-800`)은 이미 위젯과 일치한다. 테두리만 빠져 있다.

### 타이핑 시퀀스 — 3턴 루프 (약 20초)

| # | 장면 | 보여주는 것 |
|---|---|---|
| 1 | 입력창에 질문 타이핑 → 버블 전환 | 살아있는 화면 |
| 2 | 인디케이터 → 답변 스트리밍 → 출처 칩 등장 | 근거 표시 |
| 3 | 두 번째 질문 → 경고 블록 + 담당부서 안내 | **거절하는 순간** |
| 4 | 세 번째 질문 → 게시판형 목록 | 실시간 정보 |

3번이 페이지 전체의 핵심이다. "근거 없으면 답 안 한다"를 글로 읽는 것과 눈앞에서 거절당하는 걸 보는 건 설득력이 다르다.

**HTML에는 완성된 대화가 먼저 들어가고, JS는 그것을 되감아 재생만 한다.** 빈 화면에서 타이핑을 시작하면 JS가 죽는 순간 히어로가 백지가 된다.

## 9. 열린 항목

**체험 CTA 목적지 확인 필요.** `/login`이 `SignupForm`을 품고 있고 `/auth/member-signup`으로 링크한다. 두 경로 중 신규 기관 가입 진입점이 어느 쪽인지 구현 전에 확인한다.

**탐색 메뉴(Guided Menu)는 랜딩에 넣지 않는다.** 작업 목록에는 T1~T12 완료로 되어 있으나 이 브랜치에 실제로 존재하는 것은 권한 키(`menu_permissions.py`, `menu-permissions.ts`)뿐이다. 관리 화면·API 라우터·위젯 렌더가 모두 없다. 별도 확인이 필요하며, 확인 전까지 랜딩에서 언급하지 않는다.
